rev1169
=======

This revision is a minor release for Canonical OpenStack 2024.1. It includes
new features and bug fixes in the ``openstack`` snap, the infrastructure snaps,
and the charms.

Upgrade notes
-------------

To upgrade your deployment to this revision, see :doc:`Cluster upgrades
</how-to/operations/cluster-upgrades>`.

New features
------------

- A new ``sunbeam cluster refresh ingress`` command refreshes the traefik instances (traefik, traefik-public and traefik-rgw) on their own schedule, without requiring a full cluster refresh.
- TLS support for storage backends: certificates and CA material can be passed through charm configuration (with the private key stored as a Juju secret), and TLS material is validated and rendered for the ``cinder-volume`` storage backends, including NetApp.
- The ``openstack-hypervisor`` snap and charm expose the ``block-device-allocate-retries`` and ``block-device-allocate-retries-interval`` options, so that VM builds do not abort on slow Cinder backends.
- The QoS service plugin is enabled in ``neutron-k8s``.
- The ``process-all-instances`` option is available in ``masakari-k8s``.
- The OVSDB election timer can be configured in ``ovn-central-k8s``.
- The new ``cinder-volume-dellpowerflex`` charm is available for PowerFlex storage backends.

Important changes
-----------------

- Refresh commands validate that reapplying the openstack plan would not change any infrastructure application (such as traefik, mysql and vault), and the manifest is stored only after the refresh succeeds. A refresh that would change an infrastructure application is rejected instead of applied.
- The ``rabbitmq-k8s`` charm is refactored for resiliency: cheap health checks instead of load-heavy probes, missing AMQP credentials are reported as blocked, stable peer credentials are preserved across pod recreation, and transient Pebble disconnects are deferred instead of triggering cluster reformation.

Bug fixes
---------

- `LP#2129793 <https://bugs.launchpad.net/snap-openstack/+bug/2129793>`_ — maintenance mode no longer fails with node not found: node names are resolved per subsystem, openstacksdk 4.x is supported and watcher SKIPPED actions are treated as terminal
- `LP#2161593 <https://bugs.launchpad.net/sunbeam-charms/+bug/2161593>`_ — sunbeam-machine: tolerates kernels without ``linux-modules-extra``
- `LP#2161732 <https://bugs.launchpad.net/bugs/2161732>`_ — cinder-volume: NetApp TLS material is templated correctly
- `LP#2163212 <https://bugs.launchpad.net/snap-openstack/+bug/2163212>`_ — removing a node from a MAAS deployment no longer leaves leftover state: stale OpenStack and Cinder references and Ceph OSDs are removed, and empty CRUSH hosts are cleaned up
- `LP#2164695 <https://bugs.launchpad.net/sunbeam-charms/+bug/2164695>`_ — ovn-central-k8s: departed units are removed from OVN RAFT clusters
- `LP#2164877 <https://bugs.launchpad.net/snap-openstack/+bug/2164877>`_ — mysql: mysql-router-k8s is refreshed before mysql-k8s during the mysql refresh command
- `LP#2165002 <https://bugs.launchpad.net/sunbeam-charms/+bug/2165002>`_ — cinder-volume-infinidat: CHAP is opt-in and requires credentials
- `LP#2165816 <https://bugs.launchpad.net/snap-openstack/+bug/2165816>`_ — caas: errors from clusterctl commands include the stderr output in the sunbeam log file
- `LP#2167289 <https://bugs.launchpad.net/snap-openstack/+bug/2167289>`_ — the sunbeam CLI no longer fails with a permission error when reading the clusterd socket
- `LP#2168493 <https://bugs.launchpad.net/snap-openstack/+bug/2168493>`_ — NetApp backends are no longer assumed to be highly available; HA support is determined per protocol
- `LP#2168558 <https://bugs.launchpad.net/sunbeam-charms/+bug/2168558>`_ — sunbeam-clusterd: certificate rotation works when the cluster certificate has expired
- `LP#2169153 <https://bugs.launchpad.net/snap-openstack/+bug/2169153>`_ — observability: the embedded charm channel defaults from ``feature.py`` are honored when deploying with a manifest
- `LP#2169225 <https://bugs.launchpad.net/snap-openstack/+bug/2169225>`_ — the opentelemetry-collector-infra relation is created when enabling observability with an external COS
- `LP#2169709 <https://bugs.launchpad.net/bugs/2169709>`_ — openstack-hypervisor: QEMU guest agent sockets of running VMs survive snap refreshes
- `LP#2169717 <https://bugs.launchpad.net/sunbeam-charms/+bug/2169717>`_ — neutron-k8s: the ``[placement]`` section is rendered so placement resource providers and aggregates are created for routed network segments
- `LP#2169836 <https://bugs.launchpad.net/snap-openstack/+bug/2169836>`_ — sunbeam-clusterd recovers from transient HTTPS transport failures
- `LP#2170234 <https://bugs.launchpad.net/snap-openstack/+bug/2170234>`_ — SR-IOV physical function selection and PCI exclusions are honored in MAAS deployments
- `LP#2170273 <https://bugs.launchpad.net/snap-openstack/+bug/2170273>`_ — cluster refresh no longer upgrades mysql-router units when their channel changes; the openstack plan is validated against deployed infrastructure applications before it is reapplied
- `LP#2170964 <https://bugs.launchpad.net/snap-openstack/+bug/2170964>`_ — NO_PROXY ordering is stabilized, so order-only changes no longer modify ``juju-no-proxy``
- `LP#2171602 <https://bugs.launchpad.net/sunbeam-charms/+bug/2171602>`_ — tempest-k8s: QoS policy tag tests are skipped on plugin versions before 2.11
- `LP#2172299 <https://bugs.launchpad.net/snap-openstack/+bug/2172299>`_ — the non-HA cinder-volume snap is refreshed from the manifest during cluster refresh
- `LP#2172588 <https://bugs.launchpad.net/snap-openstack/+bug/2172588>`_ — sunbeam-clusterd enforces leaf-only certificate verification for mTLS authentication, preventing an authentication bypass through unverified client certificate chains

Known issues
------------

- `mysql-operators#567 <https://github.com/canonical/mysql-operators/issues/567>`_ — mysql-k8s scale-out: when scaling the MySQL cluster with ``sunbeam cluster resize``, new units can be rejected as "Old incarnation" and the InnoDB cluster can lose quorum without self-healing
- `LP#2173575 <https://bugs.launchpad.net/snap-openstack/+bug/2173575>`_ — sunbeam cluster refresh mysql: in multi DB topology deployments, ``sunbeam cluster refresh mysql`` fails with Error: 'mysql' instead of refreshing the multiple database clusters, which blocks further planned upgrades for the cluster
